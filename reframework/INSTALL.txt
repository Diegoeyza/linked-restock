Linked Restock — REFramework mod for Monster Hunter Wilds
=========================================================
Version 0.1.47

What it does
------------
Links an armour build to an item loadout and restocks it automatically. The build
is matched on the armour pieces, the jewels (skills) and the charm; the weapon is
part of the match only if you want it to be, so a mid-quest weapon swap cannot
break the link.

Install
-------
1. Install REFramework for MH Wilds (dinput8.dll in the game folder).
2. Copy linked_restock.lua to:
     <game>\reframework\autorun\linked_restock.lua
   Steam default:
     C:\Program Files (x86)\Steam\steamapps\common\MonsterHunterWilds\
3. Launch the game, open the REFramework menu (Insert) -> "Script Generated UI"
   -> "Linked Restock". The panel title shows the version.

Use
---
1. New link: pick a saved armour set and an item set from the two dropdowns, then
   press "Link selected armour set". Nothing has to be worn. Alternatively wear
   the build and press "Link current build" to capture the weapon's roll data too.
2. One link per build: ticking a link switches off any other link that would claim
   the same build.
3. Tick "Quest accepted" and/or "Back in the hub" as the triggers.
4. "Preview" shows the exact changes; "Apply now" restocks immediately.

The "Links" section is collapsed by default, scrolls, and has a Find box, so a
long list does not get in the way. The panel also shows what the mod reads:
the worn build, which link matches, and for every link the reason it does not.

How a restock is applied
------------------------
Save-data writes only. The mod never calls a game method:

  1. stacks the item set does not list, and any count above the set's, are
     returned to the item box (which also frees pouch slots),
  2. the pouch is topped up from the item box,
  3. the result is verified by re-reading the pouch.

The pouch ends up holding exactly the item set, the way the menu apply behaves;
only slot order is left to the game. Nothing is created: the item box is the hard
limit, and anything it cannot cover is reported (missing / pouch full).

Triggers
--------
- Back in the hub (default): waits until the quest is over, the results and
  end-of-quest screens are gone, loading has finished, and the game itself says
  you are at the hub/camp. Held for a few seconds before writing.
- Quest accepted (optional): waits one second so the game's own pouch setup runs
  first.

When no link matches, the per-weapon-type fallback runs, then the default item
set.

Files
-----
- reframework\data\linked_restock.json         settings and links
- reframework\data\linked_restock_trace.json   last actions (crash breadcrumb)
- reframework\data\linked_restock_failed_apply.json  only after a failed restock

Diagnostics -> "Export links" writes reframework\data\linked_restock_links.json,
which "Import links" reads back.

Notes and limits
----------------
- No hooks. The quest state is polled twice a second. No game files are modified,
  no network calls, other players are never touched.
- Field items (picked up in a hunt, not boxable) are not restockable; they are
  reported instead of invented.
- Slot order inside the pouch is not rewritten, only the contents.
- If a game patch renames an internal field, the panel reports the failing read
  instead of throwing.
- Reload after updating via REFramework menu -> "Script" -> "Reset scripts", and
  check the version in the panel title.
